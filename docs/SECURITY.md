# دليل الأمان - مؤسسة الريان واريان للشحن

## نظرة عامة

تم تطبيق معايير أمان صارمة على جميع جوانب التطبيق لحماية البيانات والمستخدمين.

## الميزات الأمنية المطبقة

### 1. التشفير
- **كلمات المرور**: تُشفر باستخدام SHA-256
- **الجلسات**: محمية بـ httpOnly cookies
- **البيانات الحساسة**: RLS على مستوى قاعدة البيانات

### 2. رؤوس الأمان (Security Headers)
- `Content-Security-Policy`: حماية من XSS
- `Strict-Transport-Security`: إجبار HTTPS
- `X-Frame-Options`: حماية من clickjacking
- `X-Content-Type-Options`: حماية من MIME sniffing
- `Permissions-Policy`: تقييد صلاحيات المتصفح

### 3. Rate Limiting
- تسجيل الدخول: 5 محاولات خلال 15 دقيقة
- API endpoints: 100 طلب خلال 15 دقيقة
- العمليات الثقيلة: 10 طلبات خلال دقيقة

### 4. Row Level Security (RLS)
جميع الجداول محمية بـ RLS:
- `app_users`: الوصول حسب الدور
- `shipments`: العملاء يرون شحناتهم فقط
- `driver_sessions`: السائقون يرون جلساتهم فقط
- `security_logs`: الإدارة فقط

### 5. Input Validation
- جميع المدخلات محمية بـ Zod schemas
- رسائل خطأ واضحة بالعربية
- حماية من SQL injection و XSS

### 6. Logging & Monitoring
- سجل أمني شامل لجميع العمليات
- تتبع محاولات تسجيل الدخول الفاشلة
- مراقبة الأداء والعمليات البطيئة
- Health check endpoint: `/api/health`

## أفضل الممارسات

### للمطورين
1. **لا تُفصح عن بيانات حساسة في logs**
2. **استخدم environment variables لجميع المفاتيح**
3. **تحقق من المدخلات في server actions**
4. **استخدم RLS policies قبل كتابة SQL**

### للإدارة
1. **غيّر كلمات المرور الافتراضية فوراً**
2. **راجع سجلات الأمان بانتظام**
3. **قم بنسخ احتياطي للبيانات أسبوعياً**
4. **فعّل التنبيهات للعمليات المشبوهة**

## الاستجابة للحوادث

### في حالة اختراق محتمل:
1. راجع `/api/health` للتحقق من صحة النظام
2. افحص security_logs في قاعدة البيانات
3. غيّر جميع كلمات المرور
4. راجع RLS policies
5. تواصل مع فريق الدعم

## التحديثات الأمنية

يُنصح بمراجعة التحديثات الأمنية شهرياً:
- تحديث dependencies
- مراجعة RLS policies
- فحص security logs
- تحديث CSP headers حسب الحاجة
